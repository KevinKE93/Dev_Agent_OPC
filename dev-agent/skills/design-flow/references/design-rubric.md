# Product Design Rubric

Use this rubric before customer-facing UI build.

## Reference Use

- User-provided references are identified and summarized.
- The design extracts patterns rather than copying blindly.
- Each reference influences specific decisions: density, navigation, components, color, type, motion, or tone.
- If no reference exists, the project records either a user-provided delegation or a generated reference board.

## UX Structure

- Primary user job is obvious in the first screen.
- Navigation matches the product complexity.
- Primary and secondary actions are visually distinct.
- Empty, loading, error, success, disabled, and long-content states are defined.
- Forms include validation, recovery, and confirmation behavior.

## Visual System

- Palette is not a generic purple/blue gradient theme unless brand-led.
- Typography has clear levels and realistic text lengths.
- Spacing uses a consistent scale and supports scanning.
- Radius, shadows, borders, and cards follow explicit rules.
- Icons are purposeful and come from a consistent set.
- Motion is functional, not decorative.

## Implementation Readiness

- High-fidelity UI has a selected formal visual target; a confirmed brief,
  sketch, product-designer prose, or local prototype is not build-ready by
  itself.
- Screens are decomposed into implementable components.
- Breakpoints are specified.
- Accessibility expectations are named.
- The design names what must be verified by functional tests,
  monkey/exploratory tests, and visual comparison, including raster calibration
  and image-diff evidence for high-fidelity UI.
